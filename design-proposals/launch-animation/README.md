## 3. 已采用的 05 · 轨道汇聚 · 最终规格

### 3.1 几何

| 量 | 值 | 为什么是这个值 |
| --- | --- | --- |
| 卡片尺寸 | **80 × 112**（1:1.4 竖版海报） | 卡内还放了一条标题线 + 一条副线，读得出是"剧集缩略图"而不是色块 |
| 轨道椭圆 | **600 × 392**（RX 300 / RY 196） | 卡轨比 = 80/300 = **0.27**，这类轨道动画的甜点区。再大就挤，再小就像撒了一把色块 |
| 轨道采样 | **72 段关键帧** | 关键帧之间是直线插值（弦），弦相对椭圆是内凹的；而且半径上叠了一层"呼吸"（一圈两个周期），采样太疏这条正弦会被采成折线，读起来是抖动而不是呼吸 |
| 卡片张数 | 6 | 60° 间隔，轨道占比 30%，疏密合适 |

### 3.2 景深与"活气"（缺一层就是假的 / 就是单调的）

| 层 | 后方 | 前方 | 作用 |
| --- | --- | --- | --- |
| `scale` | 0.66 | 1.09 | 近大远小 |
| `blur` | 1.05px | 0 | 空气透视 |
| `opacity` | 0.62 | 1.00 | 前后分离 |
| `z-index` | 1 | 3 | 真的换前后关系 |

`z-index` 的翻面点选在 **y = 0**，因为那正好是卡片离品牌最远（x = ±300）的瞬间——
翻面发生在卡片完全不压品牌的时候，所以看不出跳变。只做 scale 不做 z-index 的话，
卡片永远从品牌"上面"压过去，前后关系是假的。

除景深外，公转期间还叠了三层让它"不是六台同步的机器"：

- **呼吸**：轨道半径上 `1 + 5%·sin(2 圈周期 + 每张卡相位)`
- **摇摆**：卡片在轨道上轻微摇头 ±4.5°，相邻两张反向，像一串珠子各自在晃
- **弹入**：出场不是淡入，是冲到 1.13 再收回 1

### 3.3 时间轴（甲段 1700ms + 可挂起 + 乙段 600ms）

**时间线是两段的**，中间那一段是"等首页目录"。

#### 甲段 0 – 1700ms（跑完时所有东西都静止在"品牌 + 光晕"上，正好是一个可以挂起等待的姿态）

| 时刻 | 事件 |
| --- | --- |
| 0 – 240 | 椭圆导轨淡入 |
| 0 – 560 | 品牌结晶出场：`blur(9px)` → 0、`scale .84` → 1 |
| 30 – 730 | 公转 1.1 圈，角速度按 `1-(1-u)^1.75` 衰减；六张卡各自呼吸 + 摇摆 |
| 240 – 1240 | 导轨自己脉动两次（幅值不等） |
| 730 – 1000+ | 六张卡原地待命，按 58ms 错峰依次起飞 |
| 1000 – 1290 | 螺旋吸入：拉伸 → 挤压 → **越过中心 9% 再弹回** → 消失 |
| 920 – 1660 | 品牌**衰减余振弹簧**：`1.135×.895` 主撞 → 反向 `.918×1.082` → 按 0.082/0.054/0.038/0.019 衰减到 1，同时 ±2° 旋转摆动 |
| 960 / 1086 / 1250 | 三圈冲击波（分别打在第一次、第三次、末次撞击上，一圈比一圈大） |
| 1130 – 1630 | 品牌"充能"：`brightness 1.18` + 影子撑到 58px 模糊后回落 |
| 1240 – 1540 | 导轨收束（先向外"蓄力"再猛收进品牌） |
| 900 – 1300 | "点击跳过"提示淡入 |

#### 挂起（0 – MAX_HOLD 1500ms）

甲段跑完时看首页目录好了没有：好了就立刻进乙段；没好就挂起 ——
光晕开始缓慢呼吸、提示文字换成「正在准备首页内容…（点击跳过）」。
**必须有东西在动，否则"挂起"和"卡死"长得一模一样。**
目录在 `CatalogProvider` 挂载那一刻就开始拉了，和甲段同时起跑，所以挂起通常很短。

#### 乙段（+0 – 600ms）

| 相对时刻 | 事件 |
| --- | --- |
| 0 – 240 | 品牌淡出 |
| 110 – 550 | 标题栏 / 内容就位 |
| 150 – 600 | 导航栏就位 |
| 200 – 490 | 白幕淡出，主界面显影 |

乙段刻意比白幕早 90ms 起：等白幕透明时壳层已经基本就位，不会露出"边缘漏底"的接缝。

**为什么必须分两段而不是把总时长写长**：目录什么时候回来是数据决定的，不是设计决定的。
把动画写长只会在网络快的时候白白多等，写短又会在网络慢的时候让用户看着骨架屏。
超时（1500ms）也照常揭幕 —— 骨架屏是诚实的，卡在启动画面上不是。

### 3.4 三条实现上的硬约束

1. **同一个元素只允许有一条 `animate()`。** ⚠️ 这条是本轮最重要的一课。
   最初把"公转"和"螺旋吸入"写成两条动画，结果**公转完全没在跑**：后创建的螺旋段带
   `fill: 'both'`，它在自己的**延迟期间**就会应用 0% 帧，把公转段整个盖住 ——
   六张卡从第一帧就钉死在轨道终点，只有透明度在变。肉眼看上去"绕了一圈"，其实一张没动。
   这就是"太单调了"的真正原因。
   现在多个阶段合并成**一条关键帧轨**：用 `offset` 分段、用关键帧自己的 `easing` 控制分段节奏。
   错峰不能靠 `delay`（那会把公转相位一起推后、60° 间隔就散了），要把错峰做进 **offset 空间**
   （每张卡总时长不同、但同一起跑、公转同时收工）。
2. **品牌的回弹必须是"挤压拉伸 + 过冲 + 衰减余振"，不是"均匀放大"。**
   均匀 scale 只产生"变大"，没有任何受力感 —— 那正是"没有回弹"的原因。
   `IMPACT_SPRING` 的 X 与 Y 是反向的（体积守恒的错觉），主撞 10.5% 挤压，
   之后 4 次余振按 0.082 → 0.054 → 0.038 → 0.019 衰减。
3. **补间 `filter` 时必须把 `drop-shadow` 一起带上**（`LOGO_SH`）。
   `.ttv-launch-logo` 的 CSS 里挂着一条 drop-shadow，动画只写 `blur()` 的话
   fill 会把影子顶掉，品牌从此没有投影。同一段动画的多个关键帧，
   filter 函数列表还必须**同序同长**（blur / brightness / drop-shadow），
   否则 WAAPI 退化成离散跳变，看起来是一帧闪一下。

## 4. 十套都遵守的硬规则

1. **收尾状态逐像素一致**：10 套跑完都收敛到同一个主界面（截图 + 计算样式逐元素验证过）。
2. **不遮挡超过必要时间**：品牌遮挡最长 1.0s（01），最短 0s（09）。
3. **不出现全黑帧**：底色始终是 Mica 白玻璃，没有任何一套走 `#000`。
4. **不引入新资源**：全部 CSS + Web Animations API，没有一张新图片、没有一个新字体。
5. **内容不被搬走**：除 09 / 03 的错峰位移外，主界面元素不做长距离位移。

### 检查中真实修掉的问题

**第三轮（用户反馈"太单调了，也不够，也没有回弹"）**

16. **公转根本没在跑** —— 这是"太单调"的真正原因，也是本轮最值钱的一条。
    移植到 React 时把 `fill: 'forwards'` 换成了 `fill: 'both'`（为了让元素起始不可见），
    而"公转"和"螺旋吸入"是两条独立的动画 —— **后创建的螺旋段在它自己的延迟期间就应用了
    0% 帧**，把公转段整个盖住。六张卡从第 0 帧起就钉死在轨道终点，只有透明度在变；
    肉眼看上去"卡片绕了一圈"，其实一张都没动。
    修法：**每个元素只留一条关键帧轨**，用 `offset` 分段、用关键帧自己的 `easing` 控节奏。
    错峰改做进 **offset 空间**（每张卡总时长不同、但同一起跑），否则 `delay` 会把公转相位一起推后。
17. **品牌"没有回弹"** —— 原实现是 `scale(1) → scale(1.114) → scale(.972) → scale(1)`，
    也就是"均匀放大一点点"。均匀 scale 只产生"变大"，没有任何受力感。
    换成真正的**衰减余振弹簧轨**：X 与 Y 反向（体积守恒的错觉），
    主撞 `1.135×.895`，之后按 0.082/0.054/0.038/0.019 衰减 4 次，同时 ±2° 旋转摆动。
    实测 1286ms 处 `1.124×0.903`、1339ms 处 `0.943×1.059`，1660ms 精确回到 `1.000×1.000`。
18. **导轨是一根画死的线** —— 加了两次幅值不等的脉动，收束前先向外"蓄力"一下再猛收。
19. **前五次撞击是"哑"的** —— 只有末次一圈冲击波。改成三圈分别打在第一次、第三次、末次撞击上。
20. **光晕一路"慢慢变亮"** —— 改成脉冲式涨落，和品牌弹簧同一节拍。

**第二轮（优化 05）**

11. **05 的卡片读不出是"海报"** —— 只是纯色块。加了一条标题线 + 一条副线，并把尺寸从
    54×76 提到 80×112。
12. **05 的卡片切进导轨线里** —— 椭圆只有 17 段采样，弦相对椭圆内凹 ~7px。提到 72 段。
13. **05 的卡片永远从品牌上面压过去** —— 只做了 scale/opacity 景深，没有 z 序。
    补 `z-index` 1/2/3，翻面点选在 y = 0（卡片离品牌最远的那一刻）。
14. **05 的尾段顺序错了** —— 品牌还在淡、内容已经露出来，logo 飘在货架上。改成严格串行。
15. **品牌投影会永久消失** —— 补间 `filter` 顶掉了 CSS 的 `drop-shadow`（01/04/05/10 都中招）。
    现在所有 filter 补间都带上影子常量。

**第一轮（10 套初版）**

1. **10 套动画里的海报全部变成灰块** —— 复位逻辑用了 `el.style.cssText = ''`，把海报的
   **内联渐变色**一起清空了。改成只 `removeProperty` 掉动画会碰的那 9 个属性。
2. **04 高光显影方向反了** —— 白幕向左平移，画面是从**右**往左亮的。改成向右平移。
3. **04 的斜向渐变在 280% 背景盒上做百分比定位，色标投影被拉歪**，起始帧只盖住左半边窗口。
   改用 `mask-image` 的斜向软边——倾角在平移过程中恒定，位置可预测。
4. **04 起始/收尾各有大段"空跑"** —— 白幕宽度与位移量重新配套算过（145% 宽 / -18%→78%）。
5. **04 的品牌 logo 悬在已经显影的内容上** 约 400ms，读起来像"贴纸浮在页面上"。
   现在软边扫过窗口中心的瞬间品牌开始溶解。
6. **圆环在不需要涟漪的方案里一直挂着** —— 默认 `opacity:0`，只有 01 / 02 用动画依次点亮。
7. **海报行右侧留 320px 白** —— 6 张固定宽度卡。改成 8 张 `flex:1` 铺满。
8. **10 圆角拼合在 150ms 就飞到位了** —— 换 `cubic-bezier(.45,.05,.25,1)` 慢起，
   并加了 72% 处的定位关键帧。
9. **06 霜化消融的洞 600ms 就开完了**，后面 700ms 是死时间。重排了 400→1550 的节奏。
10. **缩放容器算错** —— `scale` 挂在已定尺寸的外层上，视觉尺寸变成 `W·s·s`。
    改成"外层定尺寸 + 内层 `scale(s)` + `transform-origin: top left`"。

**动画层是自管生命的**：跑完（或点了跳过）就 unmount，不留常驻 DOM、不留内联样式、不留 fill 状态。
`src/` 其余文件 0 改动，播放链路一行没碰。

### 接入时定下的四条边界

1. **`element.animate` + `fill: 'both'` + 跑完 `cancel()`，不用 `fill: 'forwards'`。**
   forwards 会把 `transform: matrix(1,0,0,1,0,0)` / `filter: brightness(1)` 这类恒等值
   永久钉在 TitleBar / NavigationRail / main 上 —— 等于常驻合成层。项目里已经因为同类问题
   让 NVIDIA VSR 失效过一次。`'both'` 只是为了延迟期间也停在 0% 帧（否则元素会先闪一下原样）。
2. **壳层动画的目标只有 `titlebar` / `rail` / `content` 三个。** 它们都不是 `<video>` 的祖先；
   再往外一层就已经是播放器宿主 div 的祖先了，不能动。
3. **跳过路径的收尾定时器与时间线定时器必须分开存。**
   这是实测踩出来的：一开始共用一个数组，React StrictMode 的「effect → cleanup → effect」
   会在跳过时把刚挂上的收尾闹钟一起清掉 —— 用户点了跳过、面板也透明了，但它还挂在那儿挡点击。
   另外 `skip()` 要先打 `skippedRef` 标记，效果再跑一次时直接收工；
   收尾用 `animation.finished` + 定时器**双保险**（后台标签页里 rAF 会停，只靠 `finished` 永远等不到）。
4. **三处底衬必须是同一条渐变**（`.ttv-launch` / `html,body` / `.mica-backdrop`），
   分别负责动画期间、React 挂载前的那几百毫秒、撤层之后。任何一处不一致都会跳色。

## 7. 声音（启动音效 + 入场底噪）

**零音频文件**：全部在 `src/services/launchAudio.ts` 里用 Web Audio 现场合成。
这段声音整个生命周期只有冷启动那 2.15 秒，为它引入 mp3 意味着多一份要打包、要授权、
要跟着版本维护的二进制资源 —— 几十行振荡器代码就能把这件事做完。

### 7.1 声音表

| 时刻 | 声音 | 做法 |
| --- | --- | --- |
| 0 – 2600ms | **底噪 pad** | A3 / C4 / E4 / F#4（A 小调加六度）各两个振荡器差 4 音分，过低通；起音 600ms 缓坡 |
| 30 / 79 / 128 / 177 / 226 / 275ms | 六张卡**弹入** | 880→1320Hz 正弦 70ms + 一次高通噪声点；音高按 ±5% 随机微偏，避免六下听成机器 |
| 730 – 1290ms | **汇聚吸气** | 带通噪声 380→2600Hz 扫频（Q 1.8）+ 一条 110→220Hz 爬升正弦 |
| 1000 … 1290ms | **六次撞击** | A 小调五声音阶上行 `A3 C4 D4 E4 G4 A4`，各带一个八度泛音；前两下和末次再叠一层 150→82Hz 的"落地"低频 |
| 1290ms | **末次和弦** | A4 / C5 / E5 分别延后 12ms 进入，衰减 1.15s，加一层高通噪声微光 |
| 揭幕那一刻 | **收束咻** | 带通噪声 1800→320Hz，500ms |

音高关系是设计过的，不是随手取的：五声音阶上行是"把东西一件件收进来"的经典听感，
底噪用同调（A 小调加六度）所以两者叠在一起不打架。

### 7.2 离屏量化验证

把两套 cue 排进 `OfflineAudioContext` 渲染后逐窗口测：

| 指标 | 实测 |
| --- | --- |
| 整体峰值 | **0.207** ✅ 未削顶（约 −13.7 dBFS） |
| 底噪（满载 600–720ms） | RMS 0.0176 —— 一条"能感觉到但不占位"的底 |
| 六次撞击 RMS | 0.034 → 0.037 → 0.039 → 0.040 → **0.063** → **0.073**（逐次上行，明确盖过底噪） |
| 末次和弦（1290–1700ms） | RMS 0.055、峰值 0.207（全场最响，落在"收完了"这一拍） |
| 揭幕咻（1750–2050ms） | RMS 0.022 ✅ |
| 3.2s 之后 | **完全静音**（peak = 0）✅ 没有拖尾 |

> 调过一版：汇聚 riser 的 gain 从 0.045 降到 0.028 —— 0.045 时它的 RMS 和撞击同量级，
> 听起来是一段"嘶"而不是吸气。现在撞击 RMS 是它的 1.2–2.4 倍，主次分明。

### 7.3 三条工程约束

1. **自动播放策略**：Chromium 在无手势时会把 `AudioContext` 置为 `suspended`。
   桌面端靠 `tauri.conf.json` 的 `additionalBrowserArgs` 加
   `--autoplay-policy=no-user-gesture-required` 放行 —— ⚠️ 这个字段会**覆盖** wry 的默认参数，
   所以默认那串 `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection` 必须原样带上。
   万一仍被拦（比如开发期在浏览器里跑），**静默降级成无声**：丢启动音是小事，
   让启动动画报错或卡住是大事。
2. **cue 时刻表和动画共用同一组常量**（`POP_BASE` / `SWIRL_BASE` / `IMPACT_BASE`）。
   改动画必须两边一起改 —— 错开几十毫秒，撞击就从"打中了"变成"慢半拍"。
3. **收尾必须释放 `AudioContext`**，否则 Windows 的"音量合成器"里会挂一个常驻条目。
   `dispose()` 与动画的 `cancelAll()` 分开走：动画要立刻回终态，声音要淡出，硬停会"啪"一下。

设置页「播放体验 → 启动音效」可以关掉它，与播放器音量完全独立。
